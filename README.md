# iYak32

PlatformIO/Arduino firmware for a small family of ESP32 projects. The active build runs `BASIC_MODE` as a local sensor node. The next physical project is an indoor iGrow shelf with two or three plant bins. The kayak controller and hockey scoreboard remain separate, unfinished modes.

- [RELAUNCH.md](RELAUNCH.md) explains the code, device workflow, and product roadmap.
- [MAINTENANCE.md](MAINTENANCE.md) tracks technical work and distinguishes built code from real-device checks.

## Verified sensor node

On 2026-10-09, the isolated board `ESP_15605` booted cleanly after an application-only flash. Its BMP280 sent temperature and pressure to the private MQTT broker, and Home Assistant created one MQTT device with those readings and battery, Wi-Fi, and CPU diagnostics. A BMP280 cannot measure humidity. The board's room placement and a second node have not been tested yet.

`src/main.cpp` enables `BASIC_MODE` at compile time. The `BOAT` and `HOCKEY_MODE` definitions are disabled. The firmware mounts SPIFFS, loads private configuration, starts Wi-Fi/MQTT/HTTP, and publishes telemetry. Files in `data/` are served by the ESP32 web server.

## Build and configuration

Build on the active devX checkout with `~/.venvs/iyak32/bin/pio run -e esp32dev`. `scripts/smoke_device.py` performs a read-only HTTP check against a reachable board.

After building, run the Wi-Fi password preservation regression test with the host compiler:

```sh
g++ -std=c++11 -Wall -Wextra -Werror -I src -I .pio/libdeps/esp32dev/ArduinoJson/src tests/wifi_config.cpp -o /tmp/iyak32-wifi-config-test
/tmp/iyak32-wifi-config-test
```

Copy `data/esp32config.example.json` to the gitignored `data/esp32config.json` for device-specific settings. Set `ssid`/`pass`, `mqtturl`/`mqttport`, and `mqttuser`/`mqttpass` there. The optional gitignored `data/config.txt`, based on `data/config.example.txt`, lists fallback Wi-Fi networks as `SSID:PASSWORD`. The old `mqtt.txt` file is not used by the current MQTT client.

Keep passwords and per-device files outside Git. An application flash and a SPIFFS filesystem upload are different operations: `uploadfs` can replace private files already on the board. The OTA environment requires an explicit device target. See [RELAUNCH.md](RELAUNCH.md) for the verified USB/IP and flash workflow.

## MQTT and Home Assistant

The JSON envelope is published on `esp32/data/<DEVICE_NAME>`; scalar readings are published on `sensors/<DEVICE_NAME>/<measure>` every `mqttDataIntervalSec` seconds. The envelope includes a UTC timestamp, sender, message type, and payload.

| Measure | Unit | Source |
|---|---|---|
| `temperature` | °C | Detected BMP280/BME280 |
| `pressure` | hPa | Detected BMP280/BME280 |
| `altitude` | m | Pressure estimate |
| `humidity` | % | BME280 only |
| `battery_voltage` | V | Battery ADC estimate |
| `wifi_rssi` | dBm | Wi-Fi |
| `cpu_temperature` | °C | ESP32 |

The firmware publishes retained discovery to `homeassistant/device/<DEVICE_NAME>/config` and retained availability to `sensors/<DEVICE_NAME>/availability`. Add Home Assistant's MQTT integration with the same private broker and leave discovery enabled. It groups the available readings into one device. Assign a friendly name and area in Home Assistant when the physical location is known. The pressure-derived altitude stays on MQTT but is omitted from the HA room device.

## Local UI and code map

The home page now groups ambient readings, a local temperature chart, Wi-Fi/MQTT status, device diagnostics, and configured digital-output controls. Failed requests display unknown or stale states and disable output controls until the board responds again. `/mqtt.html` observes the board's actual broker connection and bounded latest message previews, with topic filtering, pause, JSON copy/download, counters, and reconnect. `/history.html` provides local SVG charts, time ranges, and CSV export. These three pages require no Internet connection or frontend framework. Their API requests refresh every 3–10 seconds and pause while the tab is hidden.

Basic Mode uses the shared logical output state, including active-low polarity. Commands from its page, generic I/O, MQTT and physical buttons use the same output helpers. Unavailable LED outputs have an unknown indicator and disabled controls. Its controls report HTTP errors instead of assuming success. The navigation exposes the active device mode alongside the shared tools.

`/io_control.html` lists all 26 supported GPIOs, with configured pins first, current values refreshed every two seconds, search and role filters. The board reports serial, I²C, battery and BasicMode usages alongside pin capabilities. GPIO21 is currently both the saved Led1 output and I²C SDA: its output commands are disabled, its value is unavailable, and the shared usage is shown without changing the wiring or saved pin assignment.

Expand a row to edit its name, role, digital/analog type, electrical startup level, output inversion or local graph. Saving includes only enabled pins, preserves document fields and keeps an existing output logically active/inactive even when its polarity changes. BasicMode respects saved startup levels and does not restore removed outputs. Explicit HIGH/LOW startup values remain compatible with existing configurations; an empty startup value means logically OFF.

`GET /api/io/config` includes a boot-specific `_revision`. The page checks the revision in status, merges external changes into clean pins, preserves local drafts and asks for a choice when the same pin changed in both places. A save with a stale revision returns HTTP 409. Legacy MQTT `configIOs` arrays are validated patches to the same saved configuration; canonical `{ "io_pins": [...] }` payloads replace it.

Logical commands use `POST /api/io/set?gpio=15&active=1` (or `active=0`). The legacy `value=1/0` parameter still requests the electrical HIGH/LOW level. Responses report both electrical `value` and logical `active`. Add `duration_ms=1000` with `active=1` for a timed activation; the API accepts 100–3600000 ms, and the page offers whole seconds from 1 to 3600. The timer runs on the ESP32 independently of the browser and the MQTT loop, preserves its deadline through label/startup edits and switches logically OFF on expiry. An ordinary command cancels it; a new timed command replaces it.

MQTT `esp32/<device>/io/on` and `/io/off` take a decimal GPIO and command logical ON/OFF. `esp32/<device>/io/pulse` takes `{ "gpio": 15, "duration_ms": 1000 }`. Confirmed states are published retained on `esp32/<device>/io/<gpio>/state`, after commands/configuration changes and periodically every five seconds; fields include electrical `value`, logical `active` and `remaining_ms`. Removed pins clear their retained state. HTTP, MQTT and physical buttons share output state; HTTP and timer callbacks never access the MQTT client directly.

`GET /api/io/status` includes effective mode/type/label, polarity, countdown and pin usage metadata. ADC2 during Wi-Fi is unavailable rather than a false zero. Pins used by serial or I²C report `PIN_IN_USE` and their owner instead of an output state. Configuration uses `GET/POST /api/io/config` and is stored in `/io_config.json`. JSON export and optional small SVG graphs work locally.

- `src/api/Esp32.cpp`: boot, configuration, GPIO setup, and shared services.
- `src/api/WifiManager.cpp`: Wi-Fi fallback and OTA.
- `src/api/Mqtt.cpp` and `MqttCommandRouter.cpp`: telemetry, discovery, reconnect, and commands.
- `src/www.h`: HTTP routes; `data/`: SPIFFS web assets.
- `src/api/devices/`: BMP280/BME280, display, and buzzer.
- `src/BasicMode.h`, `src/Boat.h`, `src/Hockey.h`: compile-time application modes.

`tests/ui_browser.cjs` exercises desktop/mobile layouts, unavailable states, rejected commands, MQTT filtering/pause/export, and history CSV against fixture APIs. Run `node tests/ui_browser.cjs` with Playwright installed and available to Node; `CHROMIUM_PATH` optionally selects an existing browser executable and `UI_ARTIFACT_DIR` sets the screenshot directory. Device acceptance still requires checking the real board.

The I/O page also provides quick output cards, local GPIO favorites and remembered filters/search, a before/after preview of configuration drafts, and a bounded journal on the board. Favorites appear first in the output cards and do not change board configuration. The journal retains 64 events in RAM until reboot and survives page reloads. Events distinguish web, MQTT, physical button, timer, configuration, startup and debounced digital input origins. Commands and timer expiry are recorded at execution, including pulses shorter than the browser polling interval. Input changes require 30 ms of stability and main-loop sampling. The page provides origin filtering and JSON export; hiding the view does not clear the board journal. Unconfirmed requests remain local errors in the requesting tab.

`tests/io_browser.cjs` checks I/O filters, quick and row ON/OFF controls, favorites/remembered views, optional local storage, journal reload/origins/filter/export/overflow/reset and failed requests, draft previews and preservation, live zero/unavailable values, save failures, adding/removing pins, JSON export and mobile layouts against fixtures. Run it with the same Playwright environment. The native `tests/io_config.cpp` regression uses the same host compiler/include flags as the Wi-Fi test; it rejects invalid or duplicate GPIOs and incompatible ADC/output roles before saving or touching hardware.

`GET /api/io/events?after=<id>&session=<boot-id>` returns the board journal with `latest_id`, `capacity`, `now_ms`, `reset` and `lost` metadata. A boot change resets the cursor; events that aged out of the ring are reported as a gap. The ring uses fixed storage and shares the GPIO lock with commands and timers; it does not write flash.

Individual I/O discovery is retained on `homeassistant/<switch|binary_sensor|sensor>/<device>_gpio<gpio>/config`. The same device identifier groups these entities with existing sensor discovery. Digital outputs use `esp32/<device>/io/<gpio>/set` with `ON`/`OFF`, and display confirmed logical `active` state, including inverted outputs. Digital inputs expose raw HIGH/LOW as binary sensors; analog inputs expose raw ADC counts. Per-pin availability requires a numeric value and board availability, so shared I²C or unavailable ADC2 pins are unavailable. Renaming keeps the identity; removal or role changes clear obsolete discovery topics. Discovery is republished on broker reconnect and Home Assistant's `homeassistant/status` online message. `/api/mqtt/status` reports `io_discovery_ready` and `io_discovery_count`; those fields confirm publication to the broker, not acceptance in the Home Assistant UI.

Home Assistant confirms I/O state through MQTT. Configure its public origin and entity identifiers per board; installation details and physical-device receipts stay outside public Git.

Native `tests/io_events.cpp` verifies ring eviction, ordered IDs and copied labels. `tests/io_discovery.cpp` checks shared identities, command/state contracts, per-pin availability and message size. Compile them with the host flags shown above; the discovery test needs ArduinoJson's include path. The I/O browser suite also exercises short pulses, reload persistence, source filtering, export, bounded history, boot reset and independent journal failure.

The I/O page also supports five favorite pulse durations per output (defaults: 5 s, 30 s, 1 min). Edit `pulse_presets_ms` through the row editor; an empty array hides the shortcuts. These settings are saved on the board and included in export/import.

Scenes are saved in the same configuration under `scenes`: `{ "id": "test", "name": "Test", "actions": [{ "gpio": 15, "active": true, "duration_ms": 1000 }] }`. There are up to twelve scenes with 64 actions total; each scene targets each configured digital output at most once. Omitted/zero duration means continuous ON or ordinary OFF. A nonzero duration requires ON and 100–3600000 ms. `POST /api/io/scene` takes `{ "id": "test", "_revision": "<current revision>" }`; stale/empty revisions are rejected, and every target is checked before any output changes. `esp32/<device>/io/scene` accepts the same JSON ID with an optional revision. HTTP and MQTT execution reuse logical GPIO commands and timers. Journal entries retain the scene name and actual command origin, including the timer's eventual expiry after a scene rename. The built-in `all_off` scene stops available outputs and cancels their timers, reporting unavailable GPIOs in `skipped`; custom scenes fail as a whole if a target is unavailable. Scenes run only when requested, never automatically at startup.

An analog input can have `calibration`: `{ "raw_min": 3500, "raw_max": 500, "value_min": 0, "value_max": 100, "unit": "%", "clamp": true }`. The two ADC references must be distinct integers from 0 to 4095; they may be reversed. Conversion interpolates linearly, clamps to the chosen endpoint range by default, and can extrapolate when `clamp` is false. The editor previews conversion using the current raw reading and can capture it as either reference. HTTP/MQTT keep electrical/ADC `value` unchanged and add `calibrated_value`, `unit` and the calibration definition. Unavailable ADC2 readings have null raw and calibrated values. The I/O table and graph use the conversion; Home Assistant discovery keeps the sensor identity and uses its calibrated value/unit. Calibration is a user-defined mapping; no physical sensor calibration has been performed on this isolated board.

Import accepts a JSON file up to 64 KB (including whitespace), prepares a compact configuration up to 32 KB and validates it with `POST /api/io/config/validate`. That endpoint performs no writes or GPIO actions. The preview shows pin additions/removals/changes, startup polarity, pulse presets, calibration endpoints and scene actions. "Charger dans le brouillon" stages the imported GPIOs/scenes; only "Enregistrer" persists/applies them. Other board document fields are preserved and an imported revision is replaced by the current board revision. Importing an older file without scenes removes scenes in the draft, visibly in the preview. Scene drafts participate in external-change conflict handling, and a pin referenced by a scene cannot be removed or changed to an input until the scene is updated.

`tests/io_actions.cpp` verifies calibration direction/clamping, calibrated HA discovery, pulse presets and scene preflight/all-OFF plans. The I/O browser suite covers the complete edit/save/reload workflow for presets, calibration capture/preview, scene state/timers/conflicts, and import preview/staging/discard/explicit application. Device evidence is recorded in `MAINTENANCE.md`.

## Dashboard, zones and local automation

The home dashboard can pin and reorder configured inputs, outputs, climate readings and scenes. Output shortcuts use the same confirmed logical commands and favorite durations as I/O; calibrated inputs retain their raw reading. Preferences are optional browser storage keyed by board identity. Zones are simple optional `zone` strings on pins and scenes in `/io_config.json`, with I/O and dashboard filters; no separate zone registry is required. The dashboard's **Tout OFF + pause** persists the automation pause before stopping available outputs and reports skipped reserved pins. A failed pause is reported separately from a confirmed output stop.

`/automation.html` edits schedules and rules as a draft with explicit saving, revision conflicts, a pause/restart button, next execution and the last 32 attempted executions in RAM. It uses the same GPIO/scenes configuration document. A missing automation definition defaults to paused with no entries. Up to twelve schedules and twelve rules are supported. `GET /api/io/automation/status` exposes the board clock, pause state, current input values, runtime states, next schedule epochs and attempted executions. GPIO journal origins include `schedule` and `rule`; scene commands and timer expiry keep their usual context and MQTT confirmation.

Schedules store `{ "id": "morning", "name": "Morning", "enabled": false, "scene_id": "lights", "time": "08:00", "days": [1,2,3,4,5] }` under `automation.schedules`. Sunday is 0. `automation` also requires `paused`, `timezone` (`America/Toronto` or `UTC`) and a `rules` array. Toronto follows its seasonal daylight saving transitions. Schedules require a valid board epoch; a missing time disables them. Missed minutes are not caught up after boot, resume or edits. During one boot, a schedule runs at most once per local day, including the repeated fall hour; the missing spring hour is skipped. Runtime deduplication is in RAM, so a reboot before a later repeated fall hour does not retain an earlier execution record. Next-execution timestamps use the selected zone rather than the browser's zone.

Rules store `{ "id": "dry", "name": "Dry soil", "enabled": false, "scene_id": "watering", "gpio": 32, "operator": "below", "threshold": 30, "hysteresis": 5, "stable_ms": 2000, "cooldown_ms": 60000 }` under `automation.rules`. Sources are configured GPIO inputs: analog rules use `below`/`above` and calibrated values if available, digital rules use electrical `high`/`low`. Stability accepts 0.5–60 seconds; cooldown accepts 1–86400 seconds. A below-30 rule with margin 5 rearms when its reading returns to 35 or above; it fires only on a later stable crossing below 30. A true initial reading at startup, resume or recovery from unavailability does not trigger an action. An edge during cooldown is consumed rather than queued. Every ON action in a rule's scene needs an existing bounded duration; ordinary schedules may use continuous lighting scenes. Deleting a referenced pin/scene requires corresponding rule/schedule changes. New entries start disabled until explicitly enabled and saved. The main loop evaluates automations without a browser or MQTT connection; output expiry remains on its independent ESP timer.

`/commission.html` guides pin identification, name/zone/role, explicit saving and verification. Known I²C/serial usages block guided reconfiguration; input-only pins have no output or pull-resistor choices. A saved output can be tested ON for one second, with electrical/logical feedback and confirmed return OFF. Inputs show observed changes; analog inputs offer capture of two real references and a conversion preview. Unavailable or unsaved analog readings cannot be captured. Stale wizard writes return 409 instead of replacing external changes. Physical wiring, button presses and reference conditions still require the person at the board; the wizard does not claim a connected component from a label.

Configuration exports include zones and automations. Import previews/stages automations present in the file, including their enabled/pause states; older imports without that field preserve the board's automations and must still satisfy scene/pin references. No action is executed by validation or preview. GPIO/scenes/automation drafts participate in revision/conflict handling.

System and I/O JSON saves now write a `.tmp`, flush/close, verify its complete content, move the old primary to `.bak`, commit the temporary file and remove the backup after success. Loads prefer valid primary JSON and fall back to valid backup JSON; a staged temporary file is never accepted as a committed configuration. A primary that exists but cannot be read/parsed is preserved and new writes are refused rather than erasing a recoverable backup. HTTP blocks `.tmp` and `.bak` files. This improves interruption recovery within SPIFFS; it does not promise filesystem-wide durability after arbitrary power loss.

`tests/io_automation.cpp` exercises threshold edges, hysteresis/stability/cooldown, unavailable/reboot initialization, millisecond wraparound, DST schedule boundaries and interrupted save operations through a fake filesystem. `tests/control_browser.cjs` verifies personalization/order/zones, draft/save/conflict/pause behavior, the guided test/calibration flow, automation import/export and 320-pixel layouts. Use the existing native and Playwright commands; real-board acceptance is recorded in `MAINTENANCE.md`.

## Operator features — v1:16-operator

The dashboard now groups all configured readings by zone, including pins hidden from favorites. Selecting a zone shows its pins and scenes; its Tout OFF stops available outputs and gives them a 15-minute manual priority. Individual outputs offer 1 minute, 15 minutes or 1 hour of priority and an explicit Reprendre button. These controls use confirmed board state. A priority pauses automatic scenes that touch that output; manual HTTP/MQTT commands and scenes remain available. Pulse timers remain independent and still expire. Blocked schedule/rule attempts are consumed without catch-up, and a blocked scene changes none of its targets. Priority timers live in RAM and end on reboot, role changes or pin removal; ordinary name/zone edits preserve them.

Personalization saves an optional `device: { "name": "Atelier", "icon": "home" }` in the I/O document. Pin and scene `icon` fields use the same small built-in icon catalog. Names are nonblank and limited to 64 UTF-8 bytes; the alias changes the dashboard and HA device label while retaining MQTT topics and discovery unique IDs. Conflicts preserve unsaved names until explicit reload. Exports/imports include metadata; older imports without it preserve existing metadata.

Commissioning offers light, fan, pump, button, motion and soil-probe templates appropriate to GPIO capabilities. Templates fill a draft and require saving; they do not assert a component is physically connected or invent soil calibration. The I/O editor duplicates scenes and can create a one-second timed scene. Automation offers schedule/rule templates and duplication with a new ID and disabled defaults. The rule explanation shows initialization, current condition, stability, cooldown, unavailable readings and manual priority. Aperçu sans actionner evaluates the editor's validated candidate against current inputs and reports proposed targets without writing configuration or actuating outputs. Preview requires an unchanged saved source-pin definition and a later stable edge for an actual rule action.

`POST /api/io/override?gpio=15&duration_ms=60000` starts a per-output priority (1 second–24 hours); duration zero resumes automation. MQTT accepts `{ "gpio": 15, "duration_ms": 60000 }` on `esp32/<device>/io/override`. `POST /api/io/zone/off` takes `{ "zone": "Atelier", "hold_ms": 900000, "_revision": "<current>" }`; a stale revision returns 409, reserved targets are skipped and reported. `POST /api/io/automation/preview` takes `{ "config": <candidate I/O document>, "id": "<rule or schedule ID>" }`. GPIO state adds `override_remaining_ms`; automation status adds current condition, stability/cooldown time and affected output priorities.

Home Assistant discovery adds one button per saved scene, a built-in Tout OFF button and a confirmed automation-pause switch under the existing device. The switch uses `esp32/<device>/automation/pause/set` (`ON` pauses, `OFF` resumes) and retained `esp32/<device>/automation/state` feedback. Scene buttons reuse the existing scene command; availability requires all scene targets to be usable. Compact retained `esp32/<device>/io/scene/<id>/state` messages carry that result. Renames preserve identities; removed scenes clear their retained discovery/state, with the published scene IDs remembered in protected `/io_ha_scenes.json`. `/api/mqtt/status` reports `automation_discovery_count` separately from `io_discovery_count`.

Native `tests/io_operator.cpp` covers metadata, zone isolation/reserved skips, priority wraparound/expiry, consumed edges and stable HA control identities. `tests/operator_browser.cjs` covers templates/duplication, read-only preview, name conflicts, metadata import, confirmed priority controls, independent pulse expiry and desktop/390/320 layouts. Real deployment and acceptance evidence are in `MAINTENANCE.md`.
